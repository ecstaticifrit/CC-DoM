# Domain docs

This repo uses one domain context. Paths are relative to the repo root.

- Before exploring the code, read `GLOSSARY.md` and any relevant architecture decision records (ADRs) in `docs/adr/`.
- If either path is missing, continue silently. Use `domain-modeling` to record terms or decisions when the team settles them.
- Use the glossary's terms in specs, tickets, proposals, and test names. If a term seems missing, check for an existing term first. Note a genuine gap for `domain-modeling`.
- If a proposal conflicts with an ADR, cite the ADR and explain why the team should reconsider it.
