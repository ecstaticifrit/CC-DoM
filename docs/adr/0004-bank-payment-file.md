# Kavach writes a bank payment file instead of calling a payout provider

The team has no RazorpayX account. Mid-size Indian companies often pay carriers by uploading a bulk-transfer file to their bank's corporate portal, so Kavach does that job: sign-off and the payment file are written in one SQLite transaction, each bill gets one bank reference (`KV` + bill ID) and sits in exactly one line of one frozen file, and the bank statement is the only proof of payment. A kill at any moment leaves either both the sign-off and the file or neither, and a download never creates a new line. We chose this over a simulated provider because the rules allow mock data only in tests. The cost: Kavach cannot see whether the controller uploaded the file, it does not meet the brief's "payment provider's test mode" example literally, and full account numbers must appear in the file because the bank needs them (every download is counted on the receipt).
